# STM32F767 Reference

The reference target is STM32F767 with bxCAN and a bare-metal main loop. The project’s exact board assignment must be verified from the selected CubeMX configuration and linker script.

| Item | Reference requirement |
|---|---|
| CAN peripheral | CAN1/bxCAN using the generated `CAN_HandleTypeDef`. |
| CAN bitrate | 500 kbit/s reference setting; validate timing against the actual clock and transceiver. |
| CAN payload | Classic CAN, maximum eight data bytes per frame. |
| Real-time timer | TIM7 at a 1 ms cadence for CANopen processing. |
| UDS execution | Mainline-only bounded service budget. |
| Diagnostics RX | Dedicated FIFO1 exact-ID filters and static queue. |
| Memory | Linker-script-specific; bootloader, active application, CANopen NVM, diagnostic storage, and staging regions require exact addresses. |

A local Release UDS-enabled build measured `text=49,476`, `data=3,740`, and `bss=24,784` bytes on the main-branch linker/toolchain used for this review. The CubeMX generated build measured `text=43,012`, `data=3,660`, and `bss=23,476` bytes. These are reproducibility snapshots, not a production RAM budget: stack high-water marks, interrupt nesting, all personality combinations, bootloader reservation, linker placement, and board-specific memory margins still require target evidence.

The external transceiver, termination, power, standby control, isolation, connector, and physical CAN wiring remain board-level responsibilities. HIL acceptance must use the exact MCU package, clock source, board revision, and transceiver.
