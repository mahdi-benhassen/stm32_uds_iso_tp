# External Evidence Package

## Purpose

The production gate consumes a controlled evidence directory for physical CAN, HIL, Flash persistence, watchdog, profile acceptance, security, and formal conformance results. This directory is **not generated by host tests**. It must be populated by the responsible hardware, validation, security, manufacturing, and conformance owners.

Create a blank package with:

```sh
scripts/init_external_evidence_package.sh \
  --output build/external-evidence \
  --release-commit "$(git rev-parse HEAD)" \
  --board-revision BOARD-REVISION \
  --hardware-serial BOARD-SERIAL
```

The initializer creates templates with `status: PENDING`. It refuses to overwrite an existing directory. A template, a blank field, or a host-only report cannot satisfy the production gate.

## Required package contents

| Record | Responsible evidence owner | Minimum content |
|---|---|---|
| `release-evidence-manifest.json` | Release owner | Schema, exact release SHA, board revision, hardware serial, and approved `status: PASS` |
| `board_electrical_review.md` | Hardware owner | Schematic/BOM, transceiver, termination, protection, isolation, rails, and review approval |
| `physical_can_interoperability.md` | Validation owner | Analyzer traces, independent peer, bitrate/oscillator conditions, temperature, and result |
| `bus_off_campaign.md` | Validation owner | Controlled trials, recovery timing, retry limit, heartbeat behavior, and safe-state records |
| `flash_power_loss_endurance.md` | Embedded/hardware owner | Interrupted-write and power-loss trials on the exact MCU density and linker map |
| `watchdog_timing.md` | Embedded/validation owner | LSI/IWDG timing, voltage/temperature range, fault injection, and reset-cause records |
| `cia401_acceptance.md` | I/O product owner | Polarity, debounce, timing, scaling, calibration, limits, and fault behavior |
| `cia402_acceptance.md` | Drive product owner | Enabled modes, state machine, power stage, feedback, limits, quick stop, and fault reaction |
| `cia302_lss_commissioning.md` | Network/product owner | Independent peer, LSS persistence, heartbeat loss, reset/recovery, and commissioning results |
| `security_update_approval.md` | Security owner | Threat model, update design, key custody, anti-rollback, debug lifecycle, and approval |
| `formal_canopen_conformance.md` | Conformance owner | Applicable test plan/tool version, released OD/EDS/XDD, exact image hash, and archived result |
| `manufacturing_production_record.md` | Manufacturing owner | Per-board production traveler, calibration, identity, configuration, and security settings |
| `emc_environmental_report.md` | Laboratory owner | Applicable EMC/environmental standard, setup, calibration, limits, and report |
| `release-socketcan-status.txt` | CI/release owner | Native SocketCAN result or explicit unavailable status tied to physical CAN evidence |

Every record must contain machine-readable `status: PASS`, the exact `release_commit`, an `evidence_id`, and a named `reviewer` before it can satisfy `scripts/check_production_release_gate.sh --production`.

## Evidence integrity rules

The evidence package must be archived outside generated build output under controlled revision and access procedures. Test records must identify the exact board revision, hardware serial, firmware image hash, Object Dictionary/EDS/XDD hash, tool versions, environmental conditions, and date. If a procedure is not applicable, the responsible owner must record a formal approval rather than changing `PENDING` to `PASS`.

The package initializer is a handoff aid only. It never creates evidence and never changes the production release decision. The machine validator in `scripts/validate_external_evidence.py` remains fail-closed. The ordered release sequence and claim policy are summarized in [`v1_release_readiness_gate.md`](v1_release_readiness_gate.md).
